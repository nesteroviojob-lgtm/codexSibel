# Продолжение работы

## Задача и выбранные решения

Пользователь просит перенести корпоративный сайт СИБЭЛ из Figma с точным совпадением макетов, адаптивной версией и удобной админкой для разделов, товаров и карточек. Последний выбор хостинга — **Timeweb**. Размещение планируется позже, сейчас нужны код и рабочая админка. Используется собственная тема WordPress для обычного PHP-хостинга; платные плагины не нужны.

Последнее уточнение: пользователь хочет сначала посмотреть сайт и админку **локально на Windows**, а изображения разобрать позже. Для этого добавлен `start-local.cmd`: нужны только Node.js и npm, зависимости и локальный WordPress подготавливаются автоматически. Не блокировать локальный просмотр из-за отсутствующих изображений; полная визуальная приёмка и production-упаковка по-прежнему требуют оригинальной графики.

## Текущий блокер

Рабочая ветка — `codex/sibel-figma` в репозитории `nesteroviojob-lgtm/codexSibel`. Пользователь явно разрешил публикацию полного исходного кода в этом публичном репозитории. Продолжать с этой ветки и её черновика PR, сохраняя статус черновика до получения оригинальной графики и завершения визуальной приёмки. Runtime, базы и локальные учётные данные исключены из Git.

Повторная попытка 6 ноября 2026 года (Asia/Tomsk) выявила два независимых блокера:

- **Сеть Codex Cloud.** `environment_status` возвращает `observations_current: true`, режим `restricted`, политику `enforced`, `allowed_hosts: ["figma.com"]` и `effective_allowed_hosts: ["figma.com", "www.figma.com"]`. Эти домены присутствуют и в `/etc/codex/network-policy.json`. Однако `curl -I https://www.figma.com` через штатный прокси получает `HTTP/1.1 403 Forbidden`, `server: envoy` и `CONNECT tunnel failed`. Запрос оригинала `67b8e.svg` по ссылке из манифеста также завершился 403; ни один файл не получен. Проверки выполнены с разрешённым сетевым доступом инструмента, без изменения прокси. Точная причина расхождения не установлена; настройки компьютера пользователя не участвуют.
- **Лимит Figma MCP.** После успешного создания сессии и `get_design_context` для главной (`272:542`), и `download_assets` для того же узла вернули: `You've reached the Figma MCP tool call limit on the Starter plan`. Новые контексты, скриншоты и ссылки на оригиналы в этой попытке не получены. Нужен доступный лимит MCP либо предоставленные пользователем оригинальные экспорты и актуальные эталоны для всех семи экранов.

В новой среде локально была только ветка `work` с начальным коммитом `49bb800`. `git fetch origin codex/sibel-figma` через штатный прокси также получил `403 CONNECT`; доступ GitHub через shell сейчас не подтверждён. GitHub-коннектор работает: через него прочитаны PR и документация и записано это обновление. При возобновлении сначала получить рабочую ветку, не выдавать локальный начальный коммит за её актуальное состояние.

`environment_diagnostics` вернул `history_status: not_found`, `records: []`; сохранённого диагностического отчёта нет. Сетевую причину по этим данным установить нельзя.

Для продолжения нужно восстановить фактический доступ на стороне облачной среды и доступ к Figma MCP. Повторное добавление уже разрешённого домена само по себе не подтверждает исправление: проверить, что `curl -I https://www.figma.com`, получение рабочей ветки, установка зависимостей и `npm run assets` проходят штатный прокси. При повторении отказа потребуется диагностика облачной среды/поддержка Codex. Не обходить прокси или запрет сети. Если загрузка возвращает перенаправление на другой заблокированный хост, запросить добавление именно этого хоста.

Исправлены найденные по данным слоёв расхождения формы и геометрии, устранено горизонтальное переполнение. В предыдущей попытке все семь страниц проверены на 1360/1440/1024/768/390/360 px без графики, функциональные тесты пройдены. В попытке 6 ноября браузерные и функциональные проверки не запускались из-за указанных блокеров. Подробный отчёт: [VISUAL-AUDIT.md](VISUAL-AUDIT.md). Ни одного оригинального графического файла пока нет; полная проверка и упаковка по-прежнему блокируются.

После скачивания графики остальные шаги нужно выполнить до сообщения о готовности:

1. Прочитать `figma:figma-design-to-code`, создать новую Figma-сессию для этой задачи и получить дизайн-контекст со скриншотами. Узлы перечислены в DESIGN.md.
2. Проверить доступ к `www.figma.com` и выполнить `npm run assets`. Манифест `scripts/figma-assets.json` содержит 76 уникальных оригинальных PNG/SVG. URL действуют ограниченное время; при истечении обновить их через `get_design_context` соответствующих узлов. Сохранять исходные файлы без замены изображений и перерисовки SVG.
3. `npm ci`, `npm run dev`. В среде нужны разрешения на локальный сервер. Превью основано на PHP WASM; первый запуск подготавливает официальный WordPress из GitHub. Production использует обычные PHP и MySQL.
4. Сделать визуальную сверку всех семи страниц в ширине 1360 px и адаптивные проверки 1440/1024/768/390/360 px. Проверить геометрию каждого изображения и SVG, кадрирование, шрифты, отступы, меню, диалоги и формы. Публичная вёрстка пока НЕ прошла визуальную приёмку: проверять её без оригинальной графики недостаточно.
5. `npm run check`, `npm test`, `npm run package`. Упаковка должна оставаться заблокированной, пока отсутствует оригинальная графика.
6. Обновить статус README и PR после реальной визуальной проверки. Пользователь не просил публиковать сайт сейчас: перенос на Timeweb — будущий шаг.

## Что уже есть

- Семь шаблонов по высокодетальным ответам Figma; отдельный серый «прототип» не использовался.
- Адаптивная вёрстка без React/Tailwind и сборки в production.
- Локальные Vela Sans Regular / Medium / SemiBold / Bold с лицензией OFL.
- Каталог, категории, проекты, сертификаты, партнёры, настройки главной и контактов.
- Медиатека WordPress: изображения, галереи и PDF; публикация/черновики и порядок карточек.
- Заявки в приватных записях WordPress: nonce, валидация, honeypot, ограничение частоты, статусы обработки, опциональная почта.
- Семь функциональных проверок уже проходили на реальном WordPress с PHP 8.3 и SQLite: страницы, seed, вход, сохранение настроек, карточки, приватность и валидация заявок. После последующих изменений запускать актуальные проверки.

## Не предоставленные материалы

- Настоящие технические PDF товаров: в Figma есть изображение документа, но не сам PDF. Пока кнопка документа открывает форму запроса; после загрузки PDF в админке она скачивает файл.
- Юридические тексты политики конфиденциальности и пользовательского соглашения. Для них создаются черновики; их нужно заполнить и опубликовать перед запуском сайта.
- Описания и характеристики остальных товаров, кроме КТП, и подробности других проектов отсутствуют в макете. Не выдумывать характеристики: их можно заполнить в панели.
- Production-доступы Timeweb не запрашивались и не требуются на текущем этапе.
