# Продолжение работы

## Задача и выбранные решения

Пользователь просит перенести корпоративный сайт СИБЭЛ из Figma с точным совпадением макетов, адаптивной версией и удобной админкой для разделов, товаров и карточек. Последний выбор хостинга — **Timeweb**. Размещение планируется позже, сейчас нужны код и рабочая админка. Используется собственная тема WordPress для обычного PHP-хостинга; платные плагины не нужны.

Пользователь уже запустил сайт и админку **локально на Windows** с Node.js 26.13.0 и вернулся к задаче получения изображений. Запуск — двойной щелчок по `start-local.cmd`, без Node REPL. Состояние WordPress хранится в `.runtime/site`, случайный пароль — в `.runtime/site-credentials.json`; не удалять их при обновлении исходников. Полная визуальная приёмка и production-упаковка по-прежнему требуют оригинальной графики.

Добавлены версия локальных изображений по `filemtime`, `Cache-Control: no-store` в локальном сервере и возврат к оригиналу при пустом поле `hero_image`. Явно выбранный в админке URL не перезаписывается. Для миниатюр проекта идентификатор кадрирования определяется по пути URL без параметра версии. На компьютере пользователя для получения изменений нужно распаковать `downloads/sibel-home-image-update.zip` в существующую папку проекта и перезапустить `start-local.cmd`, затем Ctrl+F5. Архив содержит четыре изменённых файла кода и оригинал первого экрана, без базы и секретов.

Сохраняется `download-images.cmd` и Node/curl-загрузчик `scripts/download-assets.mjs`: повторный запуск пропускает полученные файлы и собирает `SIBEL-FIGMA.zip` (или нумерованные архивы по ~20 MiB). Это передача пользователем файлов, доступных ему; облачная среда не обращается к запрещённому хосту.

Небольшой архив обновления `downloads/sibel-figma-download.zip` содержит только загрузчик, манифест и инструкцию. Распаковать в существующую папку проекта рядом со `start-local.cmd`. Для работы нужен уже установленный `node_modules/fflate` (есть после запуска сайта). Архив не включает runtime, базу или учётные данные. При изменении загрузчика/манифеста пересобрать этот архив.

Загрузчик проверен тремя тестами на локальном HTTP-сервере: неизменность байтов и содержимого ZIP, повторная загрузка из кеша, отказ при HTML/HTTP 410, очистка временных файлов и валидация манифеста. Все 76 ссылок в этой среде не проверялись; временные URL могут истечь. `npm test`: 14 проверок прошли после получения графики и изменения обработки изображения первого экрана; проверены как выбор изображения администратором, так и пустое значение. `check --code-only` прошёл с предупреждением об одном отсутствующем файле.

Исправлены найденные по данным слоёв расхождения формы и геометрии, устранено горизонтальное переполнение. Ранее все семь страниц проверены на 1360/1440/1024/768/390/360 px без графики. Подробный отчёт: [VISUAL-AUDIT.md](VISUAL-AUDIT.md). Теперь графика получена, кроме одной фотографии; полная визуальная приёмка семи страниц ещё не выполнена, упаковка остаётся заблокированной.

После скачивания графики остальные шаги нужно выполнить до сообщения о готовности:

1. Прочитать `figma:figma-design-to-code`, создать новую Figma-сессию для этой задачи и получить дизайн-контекст со скриншотами. Узлы перечислены в DESIGN.md.
2. Получить от пользователя оставшийся `5c50a.png` и перенести оригинал в папку темы. Остальные 75 уже там. Альтернатива при разрешённом сетевом доступе — `npm run assets`. Манифест `scripts/figma-assets.json` содержит 76 уникальных оригинальных PNG/SVG. URL действуют ограниченное время; при истечении обновить их через `get_design_context` соответствующих узлов. Сохранять исходные файлы без замены изображений и перерисовки SVG.
3. `npm ci`, `npm run dev`. В среде нужны разрешения на локальный сервер. Превью основано на PHP WASM; первый запуск подготавливает официальный WordPress из GitHub. Production использует обычные PHP и MySQL.
4. Сделать визуальную сверку всех семи страниц в ширине 1360 px и адаптивные проверки 1440/1024/768/390/360 px. Проверить геометрию каждого изображения и SVG, кадрирование, шрифты, отступы, меню, диалоги и формы. Публичная вёрстка пока НЕ прошла визуальную приёмку: проверять её без оригинальной графики недостаточно.
5. `npm run check`, `npm test`, `npm run package`. Упаковка должна оставаться заблокированной, пока отсутствует оригинальная графика.
6. Обновить статус README и PR после реальной визуальной проверки. Пользователь не просил публиковать сайт сейчас: перенос на Timeweb — будущий шаг.

## Не предоставленные материалы

- Настоящие технические PDF товаров: в Figma есть изображение документа, но не сам PDF. Пока кнопка документа открывает форму запроса; после загрузки PDF в админке она скачивает файл.
- Юридические тексты политики конфиденциальности и пользовательского соглашения. Для них создаются черновики; их нужно заполнить и опубликовать перед запуском сайта.
- Описания и характеристики остальных товаров, кроме КТП, и подробности других проектов отсутствуют в макете. Не выдумывать характеристики: их можно заполнить в панели.
- Production-доступы Timeweb не запрашивались и не требуются на текущем этапе.
